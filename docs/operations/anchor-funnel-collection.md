# 主播新版漏斗五项采集

2026-11-27 对用户已登录的复盘页面刷新，监听实际请求后确认数据接口：

`GET https://compass.jinritemai.com/compass_api/author/live/live_room_detail/flow/flow_analysis`

场次参数为 `live_room_id`。使用官方页面在现有登录环境中生成的请求，采集响应，不从元素文本读取数值，不保存 Cookie 或签名到源码。

响应 `data.gmv_change` 数组按 `index_name` 读取“直播间曝光人数”“直播间观看人数”“成交人数”；`data.interaction_change` 读取“内容互动人数”。本次实际响应的 `index_code` 为空，不能据此编造英文接口字段名。人数要求单位 `number`、非负整数；保留精确原值，不将页面显示“万”字样作为精度来源。

同一响应内没有独立的观看互动率字段。按互动漏斗语义计算 `内容互动人数 / 直播间观看人数`，保留小数比例，展示时乘100。页面实测681位观看、59位互动显示8.66%，与此公式一致。固定响应样例679位观看、59位互动显示8.69%。观看人数为0时比例为空，不伪造0%。不是累计快照的比例差值。

App 新增隐藏复盘采集页，和百应大屏使用同一 WebView2 登录环境；每次采集按所选场次打开复盘页，监听并读取一次有效漏斗响应。大屏六项和漏斗响应各自保存采集时间，通过同一场次ID关联。两份响应不是同一时刻快照，不对外宣称原子一致；漏斗的观看及互动只取同一响应。

采集完成条件为：大屏必要数据齐全、直播间名称已确认、漏斗数据已读取且场次一致。场次切换/退出登录/超时/完成采集时关闭辅助采集页；晚到的旧场次或旧采集响应不覆盖新状态。两组漏斗的曝光、观看不一致时拒绝合并，日志显示原因。

采集状态新增 `funnel_exposure_ucnt`、`funnel_watch_ucnt`、`funnel_pay_ucnt`、`funnel_interact_ucnt`、`funnel_watch_interact_ratio`，是 App 内部字段，不冒充平台接口字段。展示区新增独立“复盘漏斗”，不用大屏 `watch_ucnt` 替代复盘观看人数。旧互动估算不作为新版互动人数展示。

验证：浏览器实际刷新成功定位请求、解析响应、核对显示；固定脱敏样例测试覆盖精确人数、比例、缺失、单位错误、两组不一致、零分母、业务错误；.NET 构建/发布、桌面UI构建、10项资源哈希验证通过。内置双页面流程已编译，尚未使用新二进制登录百应做端到端实机验证。

当前为本地预览，未发布自动更新，未改线上数据库和新版上报接口，未删除或作废历史主播数据。完整新版上报还需接入这十项的存储、区间规则及旧数据归档策略。
