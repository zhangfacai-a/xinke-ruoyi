# 人员与权限使用说明

入口：**人员与权限 → 人员列表**。姓名是人员真实姓名（原“用户昵称”），登录账号是登录用的账号（原“用户名称”）；底层字段和历史业务关联保持不变。搜索同时匹配姓名、账号和手机号。账号启停是系统访问状态，不等同于人事在职状态。

点击姓名或“详情”，集中查看四个页签：

- **基本资料**：姓名、登录账号、手机号、邮箱、部门、资料来源以及待交接事项。点击“编辑资料”修改；既有登录账号在编辑表单中只读。离职先安排交接并停用账号，历史业务归属保留。
- **店铺与直播间分工**：显示职责和人员组来源。通过“店铺与人员组”“直播间分工”入口调整，共享客服只需修改人员组。有效业务分工继续触发已有自动权限规则。
- **功能与数据权限**：管理员可以配置个人运费权限，其他业务显示原有角色授予的页面及来源。
- **系统角色与授权来源**：维护人工系统角色，查询各权限来自哪个角色。自动业务角色及个人运费入口角色不可在这里手动分配或取消。

**岗位与通用权限**维护可复用的系统角色组合；“组织岗位”是组织信息，单独选择岗位不会自动授予业务功能。现有系统角色继续保留，未按人员姓名猜测或重分配岗位。

## 运费个人权限

选择查看明细、查看看板、新增、编辑、导入、导出。使用其他动作必须同时允许查看明细。只有管理员角色可保存个人运费权限；查询仍受原有用户数据范围限制。

查看范围和操作范围分别设置：

- **本人明细**：查看或编辑本人录入的记录。新增、导入仅限本人已分配的有效客服店铺；编辑本人原记录仍要求店铺有效，改到其他店铺时重新校验目标范围。
- **负责店铺**：按照客服或客服管理员的店铺分工确定店铺范围，允许查看或操作这些店铺内的明细。没有分工时不返回全部数据。
- **指定店铺**：分别选择允许查看、允许操作的店铺，不需要额外添加客服岗位。
- **全部店铺**：对应查看或操作全部店铺，新增和保存仍拒绝停用店铺。

可以配置“全部店铺查看、仅指定店铺操作”。查看全店铺不再隐含操作全店铺。导出遵守查看范围，导入遵守操作范围。保存个人配置后，该账号的运费行为按个人配置执行，即使历史角色仍包含旧权限，也不会绕过新的配置。没有个人配置的账号沿用原有业务规则。

取消所有功能并保存，可关闭此人的运费访问。后台动作和数据范围立即生效，已打开页面的按钮及侧边栏刷新后更新。未重载的旧页面即使还显示按钮，后台也会拒绝。权限变更保留操作人、时间、前后配置；多人同时修改时，后保存者需刷新，避免覆盖。

## 钉钉与导入

钉钉同步更新绑定人员的姓名、手机号、部门等资料，**不再改写既有登录账号**。网站本地停用标记、业务分工、个人运费配置不由钉钉覆盖。未绑定钉钉的账号显示来源“网站”。

新人员导入模板和导出统一使用“姓名”“登录账号”；旧模板“登录名称”“用户名称”仍能识别。不要把账号填到姓名列。

## 发布与验证

执行 `migrate_personnel_permissions.py --apply`，增加个人运费配置和权限审计表、整理导航，同时将已有“全店铺查看＋业务操作”的既定授权转换为明确的全店铺个人配置。迁移幂等，不重写人员分工，不删除历史角色，不修改订单。

发布完整源码构建，迁移先于新程序部署。回退旧程序时新增表可保留；导航需要按发布前配置备份针对性恢复，不能用整库备份覆盖发布后业务数据。

隔离验证使用 `test_personnel_permissions.py`，只连接 `127.0.0.1:18083`：覆盖指定店铺越界拒绝、本人范围、空分工、只读动作、立即撤权、并发版本检查、自动角色保留和姓名搜索。生产不写入测试订单。
