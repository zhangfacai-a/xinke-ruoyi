# 店铺人员组与自动页面权限

先在应用数据库执行 `add-live-staff-groups-and-auto-access.sql`，核对结果应包含“直播运营”和“挽单与转推中心”两个菜单，以及 `customer_service`、`customer_admin` 两条规则，再部署后端和前端。部署时不要执行旧的整库菜单清理脚本。

旧店铺和旧人员映射保持原样。上线后，现有店铺显示为“单独配置”；管理员可以新建人员组，选择人员和店铺。人员组保存会在一个事务中更新所有选中店铺的有效人员映射。把店铺移出组只解除继承关系，保留该店铺现有人员名单，便于随后单独编辑。

把有效账号配置为启用店铺的电话客服或客服管理员后，系统授予 `auto_live_retention` 页面角色。移除最后一个符合条件的店铺岗位后，系统撤销该自动角色；通过其他角色获得的页面权限不受影响。已有订单负责人不会因人员配置变化而自动改派。后台在应用启动时和每小时 10 分核对一次自动授权，人员变更时即时核对并刷新在线用户的服务端权限缓存。已打开的浏览器侧边栏需要刷新页面才能看到新增或移除的菜单。

旧的 `add-order-retention-center.sql` 曾把挽单菜单绑定给当时所有正常角色。若希望某账号移出客服岗位后彻底看不到页面，需先检查该账号的其他角色是否仍绑定挽单菜单，并单独调整这些历史授权；本迁移不会批量撤销旧角色权限。停用店铺可以保留人员组配置，但其岗位不会触发自动授权，重新启用后会在保存时或定时核对时恢复。

其他页面要自动授权时，先创建只含对应父菜单和业务页面菜单的系统管理角色，再在 `live_auto_access_rule` 增加业务对象类型、岗位代码和角色 ID 的规则。接口应使用该页面的独立权限标识，并继续在业务层核对数据范围。不要直接给自动角色增加管理其他业务的菜单。

当前代码中的“单独配置”仍使用 `live_subject_user_map`。人员组成员变更会同步其关联店铺；店铺切换人员组会用新组成员替换该店铺原有映射。上线前应备份 `sys_role`、`sys_role_menu`、`sys_user_role` 和 `live_subject_user_map`，并在测试库先验证迁移和管理员、客服两个账号的实际访问范围。
