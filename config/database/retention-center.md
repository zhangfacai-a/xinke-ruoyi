# 挽单与转推中心

首次部署执行 `add-order-retention-center.sql`，新增订单、历史实体表和直播运营菜单。现有数据库无需为这次角色调整新增表或字段。

店铺人员保留运营，客服分为客服管理员（`customer_admin`）和电话客服（`customer_service`）。原客服映射继续作为电话客服。在店铺“配置人员”中设置两类客服，万莹等有效系统账号加入电话客服后会出现在对应店铺的分配名单中，不再按姓名写死。

客服管理员可以新增、修改其管理店铺的订单信息并分配电话客服；电话客服只能查看和跟进分配给自己的订单，不能修改店铺、原订单号、电话地址或负责人。系统超级管理员可管理全部店铺。服务端校验权限，列表、看板和下载采用相同数据范围。店铺人员配置和删除需要 `system:user:edit` 权限。

新增订单填写店铺、原订单号、电话地址、电话客服，时间由服务器记录。不再填写订单跟进信息，不提供领取入口。跟进时填写本次记录，处理进度使用点击选项。勾选“本次为客户跟进”的第一次保存时间为首次跟进时间。创建、修改、跟进、负责人变更保存在 `live_retention_history`，版本号防止并发覆盖。

挽单成功填写销售额，并清除运费；转推成功填写转推店铺、订单号和金额。其他挽单结果默认显示空运费金额框，留空表示未征收，填写金额（包括零）表示已征收，无单独勾选。完成前至少登记一种业务结果。金额不重复累计跟进记录。

删除店铺标记为已删除并清除人员映射，不再显示在配置和可选名单中，保留历史订单、店铺名称及跟进记录。

订单列表提供删除按钮，仅该店铺客服管理员及系统超级管理员可删除。确认订单号后，同时删除订单及其跟进历史；版本已变化时拒绝删除，要求刷新重试。两项删除在同一事务内执行。

列表、看板和下载按订单创建日期筛选，筛选相互独立。列表分页最多100条，CSV下载包含当前订单明细、不含完整历史；单次最多31天、5000条，后端仅允许一个下载同时执行。不自动轮询、不自动删除任务。

`configure-retention-shop-staff.sql` 配置当前12家店铺及客服人员，保留已有人员映射；缺失、同名或停用账号会终止并回滚。

`cleanup-retention-legacy-columns.sql` 在新版代码部署后清理旧数据库字段 `phone`、`description`，电话地址统一使用 `address`，跟进使用历史表及 `latest_note`。执行前备份业务表。
